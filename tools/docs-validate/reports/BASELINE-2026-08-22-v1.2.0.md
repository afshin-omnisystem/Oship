## 5. CI reality check — the installed workflow is stale

`ADOPT-OBL-13` was discharged by the repository owner, who installed
`.github/workflows/docs-validate.yml` on `main` manually. **Four real runs exist and EV4
is achieved** (see `.ai/PROJECT_STATUS.md`).

**But the installed workflow is the pre-`ADOPT-OBL-01b` version.** It provisions Python
only — no Node, no `mermaid`, no `jsdom`, and no `assert-engine.py` gate. `main` also
still carries validator **v1.1.0**, which fails *open* on engine degradation.

Consequently the CI runs to date exercised the **structural fallback**, which abstains on
612 of 1,998 diagrams and reports `MMD-PARSE PASS` regardless. **CI has never yet parsed
this corpus with an authoritative engine**, and its Mermaid result has been a false green
throughout — including while the 5 defects repaired above were live.

This is tracked as **`ADOPT-OBL-14`**. It is not a new defect; it is the already-recorded
`ADOPT-OBL-01b` defect still present on `main`, which the branch fix has not yet reached.

## 6. Reproduction

```bash
npm install --no-save --no-audit --no-fund mermaid@11 jsdom
python3 tools/docs-validate/run-validator.py --self-test
python3 tools/docs-validate/run-validator.py --reports-dir tools/docs-validate/reports
```

Expected: self-test **33/33 PASS**; corpus **FAIL — 8 errors, 443 warnings**; engine
`mermaid.parse`, `authoritative: true`, **0 invalid diagrams**.

Without the `npm install` the run reports **9** errors — the 8 above plus `MMD-ENGINE` —
and Mermaid results are `UNSUPPORTED_BY_VALIDATOR`, never `PASS`.
