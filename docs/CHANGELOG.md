# Changelog

## Sprint 030 — Unified Execution Planning & Smart Routing Engine

Added the real deterministic Execution Planning & Smart Routing layer on top of the Sprint 029 Risk Decision engine. `services/market-engine/src/execution/planning/` answers **WHAT / WHERE / WHEN / HOW** to convert a Risk-approved Allocation Decision into a deterministic, auditable, replayable **Execution Plan** — and never executes. It introduces a canonical execution plan model (execution_plan_id, allocation_id, opportunity_id, strategy_id, domain, status, requested/approved/planned/unplanned capital, venue/route/order/leg counts, execution_mode, routing_policy, slicing_policy, estimated slippage/fees/latency, expected_fill_ratio, liquidity_utilization, time_horizon, deadline, freshness, risk/allocation/aegis/treasury reference, config/policy version, timestamp, fingerprint). The lifecycle is PROPOSED→VALIDATED→ROUTED→SLICED→READY→AEGIS_APPROVED→TREASURY_AUTHORIZED→PAPER_EXECUTED→RECONCILED plus terminal BLOCKED/STALE/EXPIRED/CANCELLED/FAILED/PARTIALLY_EXECUTED with explicit deterministic transitions. Six execution modes (SINGLE_VENUE/MULTI_VENUE/SEQUENTIAL/PARALLEL/HEDGE_FIRST/LEG_FIRST) are governed by strategy semantics. A deterministic Smart Router scores healthy routes by net economics → fill probability → liquidity → slippage → fees → latency → venue ID (stable tie-break, no ML/no randomness) and enforces multi-venue allocation (sum(routes) ≤ approved; route ≤ executable liquidity). Deterministic slicing (FIXED_SIZE, PERCENTAGE, LIQUIDITY_PROPORTIONAL, VWAP_STYLE, TWAP_STYLE), partial-fill handling (FULL/PARTIAL/UNFILLED; REMAIN_ON_VENUE/REROUTE/RESIZE/CANCEL/REPLAN), atomic & coordinated legs (triangular/funding/basis/hedge/surebet groups never silently split; unavailable mandatory leg → BLOCKED), freshness/expiry re-checks (stale/expired never reach AEGIS), AEGIS + Treasury boundaries (never self-authorize; Treasury proposal is recommendation-only), fail-closed invariants, deterministic replay, and a structured audit record (`oship.execution-plan.v1`). Covered by **188 new tests** (core 25, scenarios 22, routing 17, slicing 15, partial-fill 14, replay 10, invariants 16, atomic 15, cross-domain 10, replan 15, boundaries 18, economics 11), `pnpm demo:execution-planning` (`RECONCILED`, FULL/PARTIAL/BLOCKED/REROUTED/REPLAN, AFIS + ABL unified), and updated architecture/roadmap/glossary documentation. **Execution Planning ≠ Execution Authority** — simulation only; no live exchange/bookmaker APIs, no provider credentials, no real-money movement, no authority-chain bypass, no second Portfolio/Risk/Execution authority, no ML, no routing randomness.

## Sprint 029 — Unified Portfolio Risk Decision & Risk Budget Engine

Added the real deterministic Risk Decision layer on top of the Sprint 028 Allocation engine. `services/market-engine/src/risk/decision/` answers **IS THE ALLOCATION SAFE** — the single Portfolio Risk Authority that decides whether a proposed Allocation is compatible with the current Portfolio, Risk Budget, Exposure, Correlation, and AFIS + ABL limits, or should be reduced / scaled / blocked, before passing to AEGIS/Treasury. It introduces a canonical risk decision model: projected total/domain/strategy/opportunity/position/event/correlation/instrument exposure, liquidity exposure, capital-at-risk, max loss, expected loss, risk-adjusted return, concentration, utilization, risk budget remaining, available capital, stress loss, worst-case portfolio impact, confidence, freshness, expiry, and a deterministic risk decision + reason + fingerprint. The lifecycle is PROPOSED→ASSESSED→RISK_CHECKED→RISK_APPROVED plus terminal REJECTED/RISK_BLOCKED/CAPITAL_BLOCKED/LIQUIDITY_BLOCKED/CORRELATION_BLOCKED/CONCENTRATION_BLOCKED/STALE/EXPIRED/CANCELLED. The non-binary scale is FULL_APPROVAL / PARTIAL_APPROVAL / REDUCED / BLOCKED; exposure/concentration/liquidity/drawdown/stress violations are *scalable* (they reduce approved capital to the risk-safe amount) while emergency-stop/stale/expired/all-or-nothing-below-minimum are fatal and block outright. AFIS and ABL are assessed in ONE unified risk budget with no preferential treatment. Includes versioned risk config (risk_config_version / risk_policy_version / risk_budget_version + configuration fingerprint), a unified hierarchical risk budget (total → domain → strategy → candidate), a deterministic composite risk score with observable factors (exposure, concentration, correlation, liquidity, drawdown, stress loss, capital-at-risk, freshness, confidence), a deterministic stress engine (NORMAL / ADVERSE / SEVERE / EXTREME with portfolio loss, candidate loss, domain loss, budget utilization, remaining budget), fail-closed invariant checks (allocated ≥ 0, approved ≤ requested, approved ≤ risk-safe, blocked candidate not approved, emergency stop not bypassed, all-or-nothing no sub-minimum, exposure ≤ limits, stress loss ≤ limit, budget utilization ≤ 100%), portfolio-aware projected portfolio (existing + new), dynamic reallocation-aware sequential budget accounting (a running portfolio snapshot enforces shared capital/exposure across the batch), Control integration (EMERGENCY_STOP/HALTED → BLOCKED, revalidation via CONTINUE/REVALIDATE/REJECT/EXPIRED/STALE), AEGIS boundary (APPROVED/PARTIALLY_APPROVED/BLOCKED — risk never bypasses AEGIS), Treasury boundary (proposal/recommendation only, never mutates treasury), canonical SHA-256 fingerprinting, isolated deterministic replay, and a structured audit record (`oship.risk.v1`). Covered by 120+ new tests (71 core + 49 cross-domain/stress/replay/invariant scenarios), `pnpm demo:risk-engine` (`RECONCILED`, FULL/PARTIAL/BLOCKED + all four stress scenarios), and updated architecture/roadmap/glossary documentation. Simulation only — no ML, no live exchange/bookmaker APIs, no provider credentials, no real-money movement, no authority-chain bypass, no architecture duplication.

## Sprint 028 — Unified Capital Allocation & Portfolio Optimization Engine

Added the real deterministic allocation layer on top of the Sprint 026 opportunity engine + Sprint 027 strategy engine. `services/market-engine/src/allocation/optimizer/` answers HOW MUCH of the ONE unified OSHIP Treasury should be committed to each eligible (Opportunity + selected Strategy) candidate. It introduces a canonical allocation model (allocation_id, opportunity_id, strategy_id, domain, requested/allocated/unallocated capital, allocation_ratio, expected gross/net/risk-adjusted return, capital_efficiency, confidence, liquidity, correlation_group + correlation_exposure, portfolio_exposure, risk_score, time_horizon, capital_duration, capital_turnover, reason, policy_version, configuration_version, timestamp, fingerprint), a deterministic lifecycle (PROPOSED→EVALUATED→OPTIMIZED→RISK_APPROVED→AEGIS_APPROVED→TREASURY_AUTHORIZED→ALLOCATED plus terminal REJECTED/RISK_BLOCKED/CAPITAL_BLOCKED/AEGIS_BLOCKED/TREASURY_BLOCKED/EXPIRED/STALE/CANCELLED), a validated candidate builder (with re-checked opportunity expiry/freshness, required/maximum/minimum capital, gross/net/risk-adjusted return, edge, confidence, liquidity, execution probability, correlation-group, time horizon, all-or-nothing vs partial mode derived from the strategy type), a transparent composite allocation scoring policy (Fixed / Confidence Weighted / Edge Weighted / Capital Efficiency Weighted / Risk Adjusted / Liquidity Constrained / Correlation Adjusted / Hybrid — every factor observable), and explicit capital constraints (total/domain/strategy/position/event/correlation exposure, per-candidate cap, minimum viable allocation, liquidity reserve). Allocations NEVER mutate Treasury / Portfolio / Risk / AEGIS / Execution; Allocation is proposal-only.

Core deliverable is a deterministic, bounded greedy constrained-capital optimizer: filter invalid/stale → score → sort with stable tie-breakers (risk-adjusted return, capital efficiency, confidence, opportunity id, strategy id) → clamp partial candidates to the binding capital/exposure/liquidity budget → enforce all-or-nothing and minimum-viable-allocation → verify invariants (sum(allocations) ≤ allocatable, available+reserved+allocated = total, per-domain/correlation/position/event exposure ≤ limits, allocation ≤ executable liquidity) → fail closed to ALLOCATION_BLOCKED. It is cross-domain: AFIS and ABL compete for ONE Treasury in a single optimization (no separate pools), uses the existing Risk/Portfolio/correlation/liquidity model, supports dynamic reallocation with per-candidate delta (previous/new/delta), integrates Control (REVALIDATE/REPRICE/RESIZE and EMERGENCY_STOP/HALTED → NO_NEW_ALLOCATION while keeping reconciliation/audit/replay), AEGIS (must approve, cannot override), Treasury (proposal only, remains authoritative), and revalidation, plus canonical SHA-256 fingerprinting, isolated deterministic replay, and a structured audit record (optimization_id, candidate_ids, strategy_ids, input/reserved/available capital, scores, ranking, allocations, rejections, constraints, policy/config version, decision, reason). Covered by 115+ new tests (84 core + 24 cross-domain/AFIS/ABL/scenario), `pnpm demo:allocation-engine` (`RECONCILED`, shared capital, candidates, optimization, final allocation, unallocated capital, invariants PASS, Allocation→AEGIS→Treasury→paper execution→position→reconciliation), and updated architecture/roadmap/glossary documentation. Deterministic greedy only; no ML / quadratic / linear programming this sprint (the contract is replaceable by QP/LP/CVaR/mean-variance/RL later). Simulation only: no live exchange/bookmaker APIs, no provider credentials, no real-money movement, no authority-chain bypass.
